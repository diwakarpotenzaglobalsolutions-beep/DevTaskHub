# DevTask Hub backend on AWS Windows Server

This guide deploys the existing ASP.NET Core backend to IIS on a Windows Server EC2 instance and connects it to Amazon RDS for MySQL. It does not create AWS resources for you.

Project facts used below:

| Item | Value |
| --- | --- |
| Project file | `DevTaskHubBackend.csproj` |
| Solution | `DevTaskHub.sln` |
| Target framework | `net10.0` |
| Published assembly | `DevTaskHubBackend.dll` |
| IIS process path | `.\DevTaskHubBackend.exe` in the generated `web.config` |
| IIS hosting | In-process, ASP.NET Core Module V2 |
| EF Core context | `MySqlDbContext` |
| Connection string key | `ConnectionStrings:MySqlConnection` |
| Suggested site folder | `C:\inetpub\devtaskhub` |
| Application pool | `DevTaskHubPool` |
| Roles in this codebase | Admin, Project Manager, Developer |

There is no HR role in the current database seed or `UserRole` enum. Do not add one as part of deployment.

The application does not call `Database.Migrate()` at startup. Apply migrations yourself, against the database you intend to change, after reviewing them.

## 1. Windows Server EC2 instance

1. Use a Windows Server 2019 or 2022 EC2 instance in the same VPC as the RDS instance, or in a VPC that can reach RDS on port 3306.
2. Attach a security group that allows:
   - TCP 443 from the load balancer or from the public clients who should reach IIS.
   - TCP 80 only if you need HTTP to redirect to HTTPS.
   - TCP 3389 only from your own IP, for administration.
3. Do not open MySQL port 3306 to the internet. The RDS security group should allow 3306 only from the EC2 security group.
4. Give the instance an IAM role only if you later need other AWS APIs. This backend does not use the AWS SDK.

## 2. Install IIS

On the EC2 instance, in an elevated PowerShell window:

```powershell
Install-WindowsFeature -Name Web-Server, Web-WebSockets, Web-Mgmt-Console -IncludeManagementTools
```

Confirm the default site answers on port 80, then stop using that site for this application. The DevTask Hub site will have its own binding.

## 3. Install the .NET 10 Hosting Bundle

1. On the EC2 instance, download the **.NET 10 Hosting Bundle** from Microsoft: https://dotnet.microsoft.com/download/dotnet/10.0
2. Install it. The installer registers ASP.NET Core Module V2 with IIS.
3. Restart IIS so the module is loaded:

```powershell
net stop was /y
net start w3svc
```

4. Confirm the runtime:

```powershell
dotnet --list-runtimes
```

The list must include `Microsoft.AspNetCore.App 10.x` and `Microsoft.NETCore.App 10.x`. This publish is framework-dependent (`--self-contained false`), so the server must have that shared runtime.

## 4. Publish the backend

On your development machine, from the project directory that contains `DevTaskHubBackend.csproj`:

```bash
dotnet restore
dotnet build -c Release
dotnet publish DevTaskHubBackend.csproj -c Release -r win-x64 --self-contained false -o ./publish
```

The `publish` folder is gitignored. Do not commit it.

The folder must contain:

- `DevTaskHubBackend.dll` and `DevTaskHubBackend.exe`
- `web.config` generated by the SDK, with `hostingModel="InProcess"` and `processPath=".\DevTaskHubBackend.exe"`
- `appsettings.json`
- `appsettings.Production.json`
- the referenced NuGet assemblies, including MySQL and JWT packages

`appsettings.Development.json` is excluded from publish. Development user secrets are not included.

## 5. Copy the published files to EC2

1. Stop the IIS site before replacing files on a later release. For the first copy, the site does not exist yet.
2. Copy the contents of `./publish` to `C:\inetpub\devtaskhub`.
3. Do not copy your local `secrets.json`, `.env`, or user-secrets store.
4. Grant the future application pool identity read and execute access to that folder. After the pool exists:

```powershell
icacls C:\inetpub\devtaskhub /grant "IIS AppPool\DevTaskHubPool:(OI)(CI)RX" /T
```

Logs, if you enable stdout logging, also need a `logs` folder that the pool can write:

```powershell
New-Item -ItemType Directory -Force C:\inetpub\devtaskhub\logs
icacls C:\inetpub\devtaskhub\logs /grant "IIS AppPool\DevTaskHubPool:(OI)(CI)M"
```

## 6. Create the application pool

In IIS Manager, or with PowerShell:

```powershell
Import-Module WebAdministration
New-WebAppPool -Name DevTaskHubPool
Set-ItemProperty IIS:\AppPools\DevTaskHubPool -Name managedRuntimeVersion -Value ""
Set-ItemProperty IIS:\AppPools\DevTaskHubPool -Name processModel.identityType -Value ApplicationPoolIdentity
Set-ItemProperty IIS:\AppPools\DevTaskHubPool -Name startMode -Value AlwaysRunning
```

`managedRuntimeVersion` set to an empty string is the **No Managed Code** setting. Do not select .NET CLR 4.0. ASP.NET Core runs inside `dotnet` through the hosting bundle, not through the old .NET Framework CLR.

## 7. Create the IIS website

```powershell
New-Website -Name DevTaskHub -PhysicalPath C:\inetpub\devtaskhub -ApplicationPool DevTaskHubPool -Port 80 -HostHeader api.devtaskhub.com
```

Replace `api.devtaskhub.com` with the host name you will actually use. Then add the HTTPS binding after the certificate exists:

```powershell
New-WebBinding -Name DevTaskHub -Protocol https -Port 443 -HostHeader api.devtaskhub.com
```

Point the site at `DevTaskHubPool`. The generated `web.config` loads ASP.NET Core Module V2 and starts `.\DevTaskHubBackend.exe` in-process. Leave that file as published. Change it only to set `stdoutLogEnabled="true"` while diagnosing a startup failure, then set it back to `false`.

## 8. Production environment variables

Set these on the IIS site, not in a committed file. IIS Manager → site → Configuration Editor → `system.webServer/aspNetCore` → `environmentVariables`.

Required:

| Name | Purpose |
| --- | --- |
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `ConnectionStrings__MySqlConnection` | Full RDS connection string. This overrides `ConnectionStrings:MySqlConnection`. |
| `AppSettings__Token` | JWT HS512 signing key, at least 64 UTF-8 bytes. Generate a new production value. Do not reuse a key that was ever committed. |
| `AllowedHosts` | Public API host names, for example `api.devtaskhub.com;localhost` |

The issuer and audience already match the running application:

- `AppSettings:Issuer` = `DevTask`
- `AppSettings:Audience` = `DevTaskAudience`

Override them only if you intentionally rotate those values. Existing access tokens would then fail validation until users log in again.

Optional:

| Name | Purpose |
| --- | --- |
| `AppSettings__Issuer` | Override the token issuer |
| `AppSettings__Audience` | Override the token audience |
| `Cors__AllowedOrigins__0` | First allowed browser origin, for example `https://devtaskhub.com` |
| `Cors__AllowedOrigins__1` | Next origin, for example `https://www.devtaskhub.com` |
| `ForwardedHeaders__Enabled` | `true` behind an AWS load balancer, `false` when IIS itself terminates HTTPS and the instance is open to the internet |
| `GitHub__Token` | Only if private GitHub repositories must be read |

Example connection string shape. Replace the host, user, and password. Keep the password only in the environment variable:

```text
Server=your-db.xxxxxx.region.rds.amazonaws.com;Port=3306;Database=DevTaskDB;User ID=devtaskhub;Password=YOUR_PASSWORD;SslMode=VerifyFull;SslCa=C:\certs\global-bundle.pem
```

Generate the JWT key on a trusted machine. It must be at least 64 bytes:

```powershell
$bytes = New-Object byte[] 64
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
[Convert]::ToBase64String($bytes)
```

Store that output in `AppSettings__Token`. Do not put it in `appsettings.Production.json`.

After changing environment variables, recycle the pool:

```powershell
Restart-WebAppPool DevTaskHubPool
```

Local development keeps using the .NET user secret `AppSettings:Token` and the local MySQL connection string. Production configuration does not read that secret store.

## 9. Connect to AWS RDS MySQL

1. Create a MySQL 8 RDS instance. The application uses MySql.EntityFrameworkCore with `MySql.Data`.
2. Create an empty database named `DevTaskDB`, or another name if you put that name in the connection string.
3. Create a database user that can create tables and indexes. Migrations need DDL rights. The runtime user can be the same user for a small deployment.
4. Download the Amazon RDS global CA bundle, `global-bundle.pem`, and save it at `C:\certs\global-bundle.pem`.
5. Put `SslMode=VerifyFull` and `SslCa=C:\certs\global-bundle.pem` in `ConnectionStrings__MySqlConnection`. If `SslMode` is omitted, production startup uses `SslMode=Required` and does not disable TLS. Development still defaults to `SslMode=Disabled` for the local MySQL server.
6. Production startup refuses a connection string whose server is `localhost`, `127.0.0.1`, `.`, or `(local)`.
7. RDS security group: inbound 3306 from the EC2 security group only.

The password is not written into application logs by configuration. Production turns off EF Core command and connection logging. Do not lower those log levels on the server.

## 10. Apply EF Core migrations

Review the migrations under `Migrations/` before applying them. The latest model is in `Migrations/MySqlDbContextModelSnapshot.cs`.

Run this from the development machine, with the RDS instance reachable from that machine, or from a bastion that has the .NET SDK and this source tree. Do not point this command at the wrong database.

PowerShell:

```powershell
$env:ASPNETCORE_ENVIRONMENT = "Production"
$env:ConnectionStrings__MySqlConnection = "Server=your-db.xxxxxx.region.rds.amazonaws.com;Port=3306;Database=DevTaskDB;User ID=devtaskhub;Password=YOUR_PASSWORD;SslMode=VerifyFull;SslCa=C:\certs\global-bundle.pem"
dotnet ef database update --context MySqlDbContext --project DevTaskHubBackend.csproj
Remove-Item Env:ConnectionStrings__MySqlConnection
```

Bash:

```bash
export ASPNETCORE_ENVIRONMENT=Production
export ConnectionStrings__MySqlConnection='Server=your-db.xxxxxx.region.rds.amazonaws.com;Port=3306;Database=DevTaskDB;User ID=devtaskhub;Password=YOUR_PASSWORD;SslMode=VerifyFull;SslCa=/path/global-bundle.pem'
dotnet ef database update --context MySqlDbContext --project DevTaskHubBackend.csproj
unset ConnectionStrings__MySqlConnection
```

The design-time factory reads `appsettings.json`, `appsettings.Production.json` when `ASPNETCORE_ENVIRONMENT` is `Production`, then environment variables. The environment variable wins over the localhost connection string in `appsettings.json`.

To add a new migration later, generate it locally against a development database, review the generated `Migrations/*.cs` file, commit it, publish, and only then run `dotnet ef database update` against RDS. Do not edit a migration that has already been applied.

## 11. DNS and HTTPS

1. Create a DNS record, such as `api.devtaskhub.com`, pointing at the EC2 public address or at an Application Load Balancer.
2. Install a certificate in the Windows certificate store. A practical source is AWS Certificate Manager attached to an Application Load Balancer, or a certificate imported into IIS with `win-acme` or your company CA.
3. Bind that certificate to the site on port 443.
4. If an Application Load Balancer terminates TLS, leave `ForwardedHeaders:Enabled` set to `true` and allow the EC2 instance to receive HTTP only from the load balancer. The app uses `X-Forwarded-Proto` to see the original HTTPS scheme.
5. If IIS terminates TLS directly and clients can reach the instance, set `ForwardedHeaders__Enabled` to `false` so clients cannot spoof the scheme.
6. Update `AllowedHosts` so it includes the real API host. A request whose `Host` header is not listed returns HTTP 400.
7. Update `Cors:AllowedOrigins` to the React site origin, including `https://` and no path. The checked-in production file allows `https://devtaskhub.com` and `https://www.devtaskhub.com`. Add the real origin if it is different. `AllowAnyOrigin()` is not used.

The React application calls this API with `Authorization: Bearer <token>`. Its origin must match exactly, including scheme and port.

## 12. Start and test

```powershell
Start-WebAppPool DevTaskHubPool
Start-Website DevTaskHub
```

Production does not expose Swagger. These checks do not need it.

1. `GET https://api.devtaskhub.com/api/Dashboard/Get-Dashboard` without a token should return HTTP 401 and a JSON body with `statusCode`, `message`, and `data`. The response must not contain a stack trace.
2. `POST https://api.devtaskhub.com/api/Auth/Login` with a valid user should return an access token and a refresh token.
3. `POST https://api.devtaskhub.com/api/Auth/Refresh-Token` with that refresh token should issue a new login payload.
4. From the React origin, a browser request should succeed only when the origin is in `Cors:AllowedOrigins`. Local `http://localhost` is allowed only when the environment is Development.

Windows Event Viewer → Windows Logs → Application shows ASP.NET Core startup failures. The stdout log in the next section shows the same text when enabled.

## 13. Troubleshooting

### HTTP 500.30

The process started and then exited. Typical causes in this project:

- `AppSettings__Token` is missing or shorter than 64 bytes.
- `ConnectionStrings__MySqlConnection` is missing, has no password, or still points at localhost.
- `Cors:AllowedOrigins` is empty.
- RDS rejected the TLS connection or the security group blocked port 3306.

Turn stdout logging on temporarily. In `C:\inetpub\devtaskhub\web.config`, set `stdoutLogEnabled="true"` on the `aspNetCore` element and recycle the pool. Read `C:\inetpub\devtaskhub\logs\stdout*.log`. Turn stdout logging off after the diagnosis so the disk does not fill.

### HTTP 500.31

IIS could not find a compatible ASP.NET Core runtime. Reinstall the .NET 10 Hosting Bundle and run `net stop was /y` then `net start w3svc`. `dotnet --list-runtimes` must show version 10.

### HTTP 500.19

`web.config` is invalid or the ASP.NET Core Module is not installed. Restore the published `web.config`. Do not leave a half-edited handler. Reinstall the hosting bundle if the module section is missing.

### HTTP 502.5

The module could not start the process. Check that `DevTaskHubBackend.exe` and `DevTaskHubBackend.dll` are both in the site folder, the pool is **No Managed Code**, and the pool identity can read the folder.

### HTTP 400 from the host filter

`AllowedHosts` does not include the host you used in the browser. Add that host to the `AllowedHosts` environment variable and recycle the pool.

### HTTP 401 on every authenticated call

The production signing key, issuer, or audience does not match the token. Log in again after a key change. Access tokens last 1 hour. Refresh tokens last 1 day. Those lifetimes were not changed.

### Database timeout or HTTP 503

The API maps MySQL connection failures to HTTP 503 without returning the server error text. Check the RDS security group, the endpoint, the TLS certificate path, and the stdout or event log.

## 14. Redeploy and roll back

1. Publish a new `./publish` folder from the commit you want to release.
2. Copy the current server folder aside, for example `C:\inetpub\devtaskhub-backup-YYYYMMDD`.
3. Stop the site, copy the new files over `C:\inetpub\devtaskhub`, and do not delete the IIS site. Environment variables live in IIS configuration, not in the published folder.
4. If the release contains a new EF migration, run `dotnet ef database update --context MySqlDbContext` before starting the site, using the same production connection string as the site.
5. Start the site and repeat the login check.
6. To roll back, stop the site, restore the backup folder, and start the site. Roll back the database only if the new migration is incompatible and you have reviewed the migration `Down` method. Do not run `database update` to an older migration on production unless that data loss is accepted.

Do not commit `publish/`, certificates, connection strings, or the production JWT key.
